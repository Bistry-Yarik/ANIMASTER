# AMS 2.0: локальная версия и подключение Steam

Этот выпуск не подключается к Steam и не принимает деньги. Профили — локальные тестовые личности, между которыми можно переключаться. Первый профиль в пустом хранилище становится администратором. Данные хранятся в IndexedDB профиля приложения на этом устройстве. Они не отправляются в сеть.

## Работающий локальный сценарий

Сообщество: регистрация профиля, публикация MP4/WebM с названием, хештегами и ценой, лента, лайки, комментарии, подписки, черновики, скачивание и импорт купленного видео в проект. Лента повышает вес совпадающих хештегов после лайка и сильно повышает вес подписанных авторов. Покупка убирает публикацию из общей ленты и передаёт её единственному покупателю в черновики. Бесплатные видео можно вставлять сразу.

Тестовый кошелёк: целые копейки карандаша (100 единиц = 1 карандаш). Тестовое пополнение: 1 рубль = 6 карандашей, без реальных списаний. Перевод и покупка: 5% с округлением до 0,01 карандаша, остаток получает адресат. Лайк даёт автору 1, подписка 5; повторная команда с тем же состоянием не выдаёт награду повторно. Отмена убирает награду, даже если она уже потрачена: возникает долг. Перевод и покупка требуют достаточного положительного баланса. Журнал отражает начисления, отмены и комиссии. Все изменения одной операции записываются атомарно в одной IndexedDB-транзакции.

## Граница подключения

`src/community.js`: чистая модель команд, округлений и рекомендаций. `communityCommand` возвращает новое состояние, не изменяя исходное при ошибке. `createLocalCommunity` — текущий адаптер. `setupCommunity` принимает альтернативный `transport` с методами `read()` и `command(actor, name, args)`. Серверный адаптер может заменить локальный без переписывания редактора. Данные местной демоверсии не являются действительными денежными балансами.

Для реального выпуска нужны Steamworks App ID, сервер приложения с HTTPS, постоянная база транзакций и видеохранилище. Steam не предоставляет готовую произвольную соцсеть с комментариями, торговлей роликами и этим кошельком. Можно подключить Steam-вход/проверку билетов и разрешённые Steamworks механизмы публикаций, а социальные связи, рекомендации и экономику хранить на сервере AMS.

Предлагаемый серверный контракт:

- `POST /session/steam`: проверка билета Steam на сервере; выдача сессии, SteamID берётся только из проверенного ответа Steam.
- `GET /feed?cursor=...`, `POST /videos`, `POST /videos/:id/comments`, `PUT /videos/:id/like {enabled}`, `PUT /users/:id/follow {enabled}`.
- `GET /wallet`, `POST /transfers {to, amount, requestId}`, `POST /videos/:id/purchase {requestId}`, `GET /drafts`. Суммы — целые сотые карандаша; actor вычисляется из сессии, не из запроса клиента.
- Серверная покупка: блокировка публикации и кошельков, проверка доступности и средств, запись проводок и комиссии, смена владельца и статуса в одной транзакции. Уникальный requestId защищает от повторного списания. Регистрация первого администратора также требует одной транзакции.
- Пополнение через Steam Microtransactions: сервер начинает и проверяет разрешённую операцию Steam; карандаши начисляются только после подтверждённого завершения и единожды по ID операции. Курс в UI сам по себе не выполняет оплату. Издателю потребуется настроить товар, валюту/цену и получить доступ к соответствующим API Steamworks. Секреты хранятся только на сервере.

До этих настроек кнопки реальной Steam-авторизации и оплаты отсутствуют. Локальный тестовый режим явно указан в интерфейсе.
